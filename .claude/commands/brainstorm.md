# /brainstorm

## Quick Reference

| Item | Value |
|------|-------|
| Purpose | Refine rough ideas into designs |
| Method | Socratic questioning, one at a time |
| Output | Design doc in `docs/plans/` |
| Skill | `brainstorming` |

## When to Use

- Before writing code for new features
- When requirements are unclear or ambiguous
- When exploring multiple implementation approaches
- Before creating implementation plans

## What It Does

1. **Understand context** - Reviews project state (files, docs, commits)
2. **Ask questions** - One at a time, prefer multiple choice
3. **Explore alternatives** - Propose 2-3 approaches with trade-offs
4. **Present design** - In 200-300 word sections, validating each
5. **Document** - Write validated design to `docs/plans/YYYY-MM-DD-<topic>-design.md`

## Process

Use and follow the brainstorming skill exactly as written.
