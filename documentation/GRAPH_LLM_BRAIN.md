## What is an LLM Brain?

An **LLM Brain** is an external knowledge and reasoning system that:

### Core Capabilities

1. **Structured Knowledge Storage**
   - Store facts, relationships, and concepts in a graph
   - Maintain temporal versioning (what was true when)
   - Track provenance (where did this knowledge come from)

2. **Multi-Hop Reasoning**
   - Traverse relationship chains (A cites B, which references C)
   - Perform complex queries LLMs can't do in context
   - Combine multiple reasoning paths

3. **External Memory**
   - Persist knowledge beyond conversation context
   - Update knowledge without retraining
   - Share knowledge across different AI agents

4. **Explainable AI**
   - Graph paths show reasoning chains
   - Visualize how conclusions were reached
   - Audit decision-making processes

### Why Use Graphs for LLM Brains?

| Feature | Graph DB | Vector DB | SQL DB |
|---------|----------|-----------|---------|
| **Relationships** | ✅ Native | ❌ None | ⚠️ Foreign keys only |
| **Multi-hop reasoning** | ✅ Excellent | ❌ No | ⚠️ Complex JOINs |
| **Semantic search** | ⚠️ With embeddings | ✅ Native | ❌ No |
| **Temporal queries** | ✅ Yes | ❌ No | ⚠️ Limited |
| **Explainability** | ✅ Path visualization | ❌ No | ⚠️ Query logs only |
| **Contradiction detection** | ✅ Graph algorithms | ❌ No | ❌ No |

**Best approach**: Combine all three (hybrid system)

## Architecture Patterns

### Pattern 1: Hybrid Retrieval (Vector + Graph)

```
┌─────────────┐
│   User      │
│   Query     │
└──────┬──────┘
       │
       ├─────────────────────────────────┐
       ▼                                 ▼
┌──────────────┐                  ┌─────────────┐
│   Vector     │                  │   Graph     │
│   Search     │                  │   Query     │
│  (semantic)  │                  │ (structural)│
└──────┬───────┘                  └──────┬──────┘
       │                                 │
       └────────────┬───────────────────┘
                    ▼
            ┌────────────────┐
            │   Merge &      │
            │   Rank Results │
            └────────┬───────┘
                     ▼
            ┌────────────────┐
            │   LLM          │
            │   Synthesis    │
            └────────────────┘
```

**Implementation:**

```php
class HybridBrainService
{
    public function query(string $question): array
    {
        // 1. Vector search for semantic similarity
        $vectorResults = $this->vectorStore->search($question, limit: 20);

        // 2. Extract entities from question (using LLM)
        $entities = $this->extractEntities($question);

        // 3. Graph search for relationships
        $graphResults = $this->graph->findRelated($entities, maxHops: 2);

        // 4. Merge and re-rank
        $merged = $this->mergeResults($vectorResults, $graphResults);

        // 5. LLM synthesis with full context
        return $this->synthesizeAnswer($question, $merged);
    }
}
```

### Pattern 2: Reasoning Chains

```
Question: "What precedents apply to this case?"
    │
    ├──> Extract case facts (LLM)
    │
    ├──> Find similar cases (Graph + Vector)
    │
    ├──> Traverse citation chains (Graph)
    │          │
    │          ├─> Case A cites Law X
    │          ├─> Law X amended by Law Y
    │          └─> Law Y superseded by Law Z (current)
    │
    └──> LLM synthesizes answer with reasoning chain
```

**Implementation:**

```php
class ReasoningBrainService
{
    public function findPrecedents(array $caseFacts): array
    {
        // 1. Find similar cases
        $similarCases = $this->findSimilarCases($caseFacts);

        // 2. For each case, traverse citations
        $precedents = [];
        foreach ($similarCases as $case) {
            $chain = $this->traverseCitationChain($case['id']);
            $precedents[] = [
                'case' => $case,
                'reasoning_path' => $chain,
                'current_law' => $this->findCurrentVersion($chain),
            ];
        }

        return $precedents;
    }

    private function traverseCitationChain(string $caseId): array
    {
        $query = "
            MATCH path = (c:Case {id: \$caseId})-[:CITES*1..5]->(law:Law)
            WHERE law.valid_until IS NULL OR law.valid_until > date()
            RETURN nodes(path) as chain
            ORDER BY length(path) DESC
            LIMIT 1
        ";

        return $this->graph->run($query, ['caseId' => $caseId]);
    }
}
```

```php
class TemporalBrainService
{
    public function getValidLawAt(string $lawId, string $date): array
    {
        $query = "
            MATCH (l:Law {id: \$lawId})-[:SUPERSEDES|AMENDED_BY*0..10]->(version:Law)
            WHERE version.valid_from <= date(\$date)
              AND (version.valid_until IS NULL OR version.valid_until > date(\$date))
            RETURN version
            ORDER BY version.valid_from DESC
            LIMIT 1
        ";

        return $this->graph->run($query, [
            'lawId' => $lawId,
            'date' => $date,
        ]);
    }
}
```

## Usage Examples

### Example 1: Legal Research Assistant

```php
class LegalResearchBrain
{
    public function research(string $question): array
    {
        // Phase 1: Extract key concepts
        $concepts = $this->extractConcepts($question);

        // Phase 2: Graph exploration
        $graphContext = $this->exploreGraphContext($concepts);

        // Phase 3: Vector retrieval
        $documents = $this->retrieveDocuments($question, $graphContext);

        // Phase 4: LLM synthesis
        return $this->synthesize($question, $documents, $graphContext);
    }

    private function exploreGraphContext(array $concepts): array
    {
        $context = [];

        foreach ($concepts as $concept) {
            // Find related laws
            $context['laws'][] = $this->graph->run("
                MATCH (l:Law)-[:CONTAINS_CONCEPT]->(c:LegalConcept {name: \$concept})
                RETURN l
                LIMIT 5
            ", ['concept' => $concept]);

            // Find precedents
            $context['precedents'][] = $this->graph->run("
                MATCH (d:Decision)-[:HAS_KEYWORD]->(k:Keyword {term: \$concept})
                WHERE d.binding = true
                RETURN d
                ORDER BY d.decision_date DESC
                LIMIT 5
            ", ['concept' => $concept]);
        }

        return $context;
    }
}
```

## Advanced Patterns

### Pattern 1: Probabilistic Reasoning

```php
class ProbabilisticBrain
{
    public function estimateProbability(string $outcome, array $evidence): float
    {
        // 1. Find historical cases with similar evidence
        $historicalCases = $this->findSimilarCases($evidence);

        // 2. Count outcomes
        $query = "
            MATCH (c:Case)-[:HAS_EVIDENCE]->(e:Evidence)
            WHERE c.id IN \$caseIds
            WITH c, collect(e) as evidence_list
            MATCH (c)-[:HAS_OUTCOME]->(o:Outcome {type: \$outcome})
            RETURN count(o) as positive_outcomes, count(c) as total_cases
        ";

        $result = $this->graph->run($query, [
            'caseIds' => array_column($historicalCases, 'id'),
            'outcome' => $outcome,
        ]);

        // 3. Calculate Bayesian probability
        return $result['positive_outcomes'] / $result['total_cases'];
    }
}
```

## Best Practices

### 1. Design Graph Schema for Reasoning

```cypher
// ✅ GOOD: Explicit relationship types
(Case)-[:CITES {context: "supporting"}]->(Law)
(Case)-[:CONTRADICTS {severity: 0.9}]->(Case)

// ❌ BAD: Generic relationships
(Case)-[:RELATED_TO]->(Law)
```

### 2. Use Temporal Properties

```cypher
// ✅ GOOD: Track validity periods
CREATE (l:Law {
    id: 'law-123',
    title: 'Criminal Procedure Act',
    valid_from: date('2020-01-01'),
    valid_until: date('2023-12-31')
})

// Query: What was valid at specific time?
MATCH (l:Law)
WHERE l.valid_from <= date('2022-06-15')
  AND (l.valid_until IS NULL OR l.valid_until > date('2022-06-15'))
```

### 3. Combine Vector + Graph

```php
// ✅ GOOD: Hybrid approach
$vectorResults = $this->vectorStore->search($query, limit: 50);
$graphResults = $this->graph->findRelated($vectorResults, maxHops: 2);
$merged = $this->rerank($vectorResults, $graphResults);

// ❌ BAD: Graph only (misses semantic similarity)
$results = $this->graph->findByKeywords($keywords);
```

### 4. Cache Expensive Queries

```php
// ✅ GOOD: Cache PageRank results
$cacheKey = "pagerank_results_" . date('Y-m-d');
$results = Cache::remember($cacheKey, 86400, function() {
    return $this->graph->computePageRank();
});

// ❌ BAD: Recompute on every request
$results = $this->graph->computePageRank();
```

### 5. Limit Graph Traversal Depth

```cypher
// ✅ GOOD: Limit hops
MATCH path = (a)-[*1..3]->(b)
RETURN path
LIMIT 100

// ❌ BAD: Unbounded traversal
MATCH path = (a)-[*]->(b)  // Can explore entire graph!
RETURN path
```

### 6. Use Indexes for Performance

```bash
# Create indexes on frequently queried properties
php artisan neo4j:create-indexes

# Verify indexes are used
EXPLAIN MATCH (l:Law {id: 'law-123'}) RETURN l
```

### 7. Implement Graceful Degradation

```php
try {
    // Try graph-enhanced response
    $context = $this->graph->getContext($query);
} catch (GraphException $e) {
    // Fall back to vector-only
    Log::warning('Graph unavailable, using vector-only mode');
    $context = [];

return $this->llm->generate($query, $context);
```

## Performance Optimization

### 1. Batch Operations

```php
// ✅ GOOD: Batch inserts
$this->graph->transaction(function($tx) use ($documents) {
    foreach (array_chunk($documents, 100) as $batch) {
        $tx->run("
            UNWIND \$docs AS doc
            CREATE (d:Document)
            SET d = doc
        ", ['docs' => $batch]);
    }
});

// ❌ BAD: Individual inserts
foreach ($documents as $doc) {
    $this->graph->run("CREATE (d:Document) SET d = \$doc", ['doc' => $doc]);
}
```

### 2. Projection for Large Results

```cypher
-- ✅ GOOD: Return only needed fields
MATCH (d:Decision)
RETURN d.id, d.title, d.date
LIMIT 1000

-- ❌ BAD: Return entire nodes
MATCH (d:Decision)
RETURN d
LIMIT 1000
```

### 3. Use Graph Algorithms Library

```cypher
-- ✅ GOOD: Use GDS for PageRank
CALL gds.pageRank.stream('myGraph')
YIELD nodeId, score

-- ❌ BAD: Custom Cypher (slow)
MATCH (n)<-[r]-()
WITH n, count(r) as inDegree
RETURN n, inDegree
```
