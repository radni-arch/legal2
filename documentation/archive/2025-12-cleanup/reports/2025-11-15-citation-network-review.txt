🔴 MEDIUM RISK: Unescaped Variable in Raw SQL

  Location: DecisionCitationService::findVectorSimilarDecisions()
  Lines: 320, 323

  Vulnerable Code:
    DB::raw("1 - (cdd.embedding <=> '{$embedding}'::vector) as similarity")
    ->whereRaw("1 - (cdd.embedding <=> '{$embedding}'::vector) >= ?", [$threshold])

  Analysis:
    - Variable $embedding interpolated directly into raw SQL
    - Source: Database field ($sourceDecision->embedding at line 204)
    - NOT direct user input, but database-stored data
  
  Risk Factors:
    Likelihood: LOW - data from database, not user input
    Impact: HIGH - arbitrary SQL execution if exploited
    Overall: MEDIUM

  Exploitation Scenario:
    1. If embedding data corrupted in database
    2. If bug in embedding storage allows SQL injection payload
    3. Malicious database write access

  Recommended Fix:
    // Validate vector format before use
    if (!$this->isValidVectorFormat($embedding)) {
        throw new CitationException('Invalid embedding format');
    }
    
    // Or use parameterized queries if pgvector supports it

Other SQL Queries:
  ✅ All other queries use Eloquent ORM or query builder with parameter binding
  ✅ No user input directly concatenated into SQL
